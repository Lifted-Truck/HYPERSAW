SWARM✱ aesthetics lab

Bench for auditioning control aesthetics — human request 2026-08-17: "could we start a lab for testing alternative aesthetics? I want to play around with a lighter color scheme, styles like skeuomorphism, rotary dials instead of sliders, etc." It settles nothing about DSP and touches no plugin parameter — this file is not connected to the running instrument and never pretends to be (no bridge, no CLAP param ids, no audio at all: it is silent on purpose, since wiring in sound would imply a live parameter path that does not exist here). What it settles is how a control should look and feel to operate. Six panels below render the SAME six controls — three continuous, one bipolar, one stepped enum, one toggle — crossed three themes (dark / light / skeuomorphic) × two widget styles (linear / rotary). All six renderings of a given control share one value: drag any of them and every other rendering updates too, so the comparison is honestly the same parameter six times, never six that quietly drifted apart. Drag a dial vertically or tab to it and use the arrow keys — see the code comment by bindDialDrag for why vertical, not angular.
1.00×
Plugin control real estate is fixed by the host, not by us — a style that reads fine at lab scale can become a smear of pixels at the size a DAW actually gives a synth. This slider scales every rendering's geometry at once (canvas AND CSS both read the same density value — see dialGeom() and the --density custom property), so "does this survive small" is a drag, not a guess.
