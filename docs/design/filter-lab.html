SWARM✱ filter lab

Lab campaign 3 item 2 — the human's verdict on the E1 cores was "not quite there yet", so this bench starts by measuring why rather than guessing. The shipped bank was measured first (`filter_core.h`, `processExternal`, swept steady-state at 48 kHz) and three concrete defects came out, all reproduced live below: it is a band-pass hump with no filter topology (rolls off on BOTH sides in every configuration); its low end is 24 dB down at default and gets WORSE as Q rises (28 dB); and most importantly the resonance knob is a backwards volume knob — peak output falls +0.98 → −3.21 → −9.32 dB as qbase goes 0.1 → 0.5 → 0.9, because summing N unity-gain bandpasses captures less total energy as they narrow. Turn up resonance, get quieter and thinner: that is almost certainly the feel behind the verdict. Each fix is a switchable variant so you can hear whether it earns its place, with a conventional multimode alongside for the "how would this sit in the rack" question. Keys A..;, Z/X octave, space drone.

Filter under test

Q compensation divides the bank sum by its own measured power gain so resonance stops being a level control. LF preserve adds back the input below the lowest band (one-pole, corner = lowest band frequency) — the bank has no DC path at all, so a rack filter built on it loses the body of anything it touches.

Measured, not drawn from a formula: the response is swept sine-by-sine through the ACTUAL filter code this page runs, steady-state RMS out ÷ RMS in, the same method used on the C++ core. Q sweep → level swing is the headline number — it re-measures peak output at qbase 0.1 / 0.5 / 0.9 and reports the spread. Under ~2 dB means resonance is a character control; 10 dB+ means it is a volume knob.

Read this number only for the BANK topologies. On the conventional multimode it measures the opposite thing and looks alarming for the wrong reason: a resonant filter is SUPPOSED to grow a peak at its corner as Q rises (measured here at +14.4 dB, a 33 dB "swing"), and that peak is the feature. The bank's 9 dB is a collapse — the whole curve sinking — while the conventional filter's is a peak rising out of an otherwise stable curve. Same statistic, opposite meaning; compare curves, not just the row.

Swarm bank

Placement, Q law and SVF coefficients are transcribed from filter_core.h — the same `2·20^qbase` Q, the same TPT SVF, the same ERB/log/harmonic laws with the 40 Hz floor and 11 kHz ceiling.

Fidelity, stated honestly. Band POSITIONS come from this page's own seeded draw, not `forcecore::buildOffsets`, so the absolute curve is not the core's curve sample-for-sample. Both defects follow from summing unity-gain bandpasses and so survive any particular draw. Do not read absolute dB here as a core measurement; read the diagnostics and the variant comparisons.

Key tracking

Shipped behaviour is 0 — the effect path does not follow the note at all. `setNoteFreq` moves only the gravity centre, and only when placement is harmonic. At 1.0 the bank centre transposes 1:1 with the played note relative to the reference key. This is the second thing the brief asked about, and it is currently absent rather than wrong.
